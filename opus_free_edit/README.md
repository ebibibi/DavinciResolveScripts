# Agentic free-form edit (experiment)

The advanced route (ADR-015) asks the model for one strict JSON plan and renders it
deterministically. This experiment does the opposite: a `claude -p` session receives the
transcript, frames and tools and makes **every** editorial decision itself - structure, cuts,
overlays, stingers, previews, self-review, final render, title and description.

Only the steps that are the same for every recording are scripted:

| step | script | notes |
|---|---|---|
| probe, 16 kHz audio, 540p proxy | `prepare.sh` | proxy is used for previews |
| Whisper large-v3-turbo with word timestamps | `prepare.sh` | runs on the GPU host (`WHISPER_HOST`, default `spark`) |
| name and sign-off normalised in the transcript | `fix_transcript.py` | Whisper prompt describes them; the script fixes remaining variants |
| silence map, frames every 10 s, 4x4 contact sheets | `prepare.sh` | inputs for the agent |
| slides of the deck that was presented (optional) | `prepare.sh` with `DECK_SLUG` | uses `npm run capture:video` in presentations-web (`PRESENTATIONS_REPO`) |
| the edit | `claude -p` with `brief.md` | model: `EDIT_MODEL` (default `claude-opus-5-5`) |
| token and cost summary | `usage_report.py` | reads the stream-json log |
| fallback voice flagged loudly | `tts_guard.py report` / `announce` | reads `"voice"` in `work/**/clips.json`; writes `out/VOICE_WARNING.md`, a banner atop `EDIT_NOTES.md`, and a Discord message with the upload URL |
| thumbnail generated by GPT Image from his video frame (series badge, headline, motif) | `ai_thumbnail.py` | the face photo is the reference image; the real logo is pasted top-right |
| thumbnail must show the whole head (gate before upload) | `check_thumbnail.py` | YuNet face detector; rejects text, panels, gradients or the logo over the head |
| keep the real embroidered MVP logo (paste in `ai_thumbnail.py`, gate before upload) | `mvp_logo.py` | SIFT match against `reference/mvp_logo/shirt_logo.png` below the face; real frame pixels only, scaled by the face-size ratio |
| no silence left in the presenter's parts | `check_silence.py` | measured from the audio, not from Whisper word timestamps |
| private upload with title, captions, thumbnail | `upload_private.py` | never public; leaves `~/video-jobs/handoff/<video_id>/` so the post-upload automation keeps the editor thumbnail |

```bash
# Usual case: he uploads the recording to ~/tmp/movies; wait for it, capture the deck, edit, upload private.
DECK_SLUG=<deck slug> opus_free_edit/start.sh latest ~/video-jobs/<yyyymmdd-topic>
# A specific file instead:  opus_free_edit/start.sh /path/to/recording.mkv /path/to/job-dir [--no-upload]
```

`start.sh` runs `run.sh` in its own systemd user unit (`video-edit-<job>`) and logs to `<job dir>/run.log`.
`setsid nohup` is not enough when the caller is a service: the job stays in the service's cgroup, and
restarting the service kills it.

`<job dir>/appendix.md` (optional) is appended to the brief for one recording; `<job dir>/STATUS` ends as
`done` or `failed` (poll it from a waiter). The brief's standing rules come from the presenter's reviews;
`editing-techniques.md` is the researched catalogue of editing techniques (sources included) and
`reference/<job>/` keeps the scripts and EDIT_NOTES of a well-received edit for the next agent to reuse.
`tools/ebifry_clip.py` makes the えびフライ cameo clips (Gemini TTS; when Gemini is out of credits or over its daily
quota it falls back to Irodori-TTS by itself and records the voice of each clip).

No Gemini check before editing: the prepayment tops itself up (2026-11-21), so a test request per job would
only spend money. If a clip still falls back to another voice, `tts_guard.py report` / `announce` flag it after
the edit (no API calls).

The job directory keeps everything the agent produced: `work/` (its EDL, render scripts,
agent log) and `out/` (`final.mp4`, `youtube.json`, `captions.srt`, `thumbnail.png`,
`EDIT_NOTES.md`, `USAGE.md`). `EDIT_NOTES.md` lists the steps the agent itself found mechanical;
those are the candidates to move into `prepare.sh` next.

The agent runs with `--permission-mode bypassPermissions` inside the job directory. Run it only on
recordings you own, on a machine where that is acceptable.

## Shorts mode (vertical shorts for the SNS post queue)

The same free-form idea for TikTok / Instagram / Facebook / Threads / X: the agent watches a finished long video
and plans and edits vertical 9:16 shorts that stand on their own on each platform — how many, which ideas, the hook,
えびフライ, telops, layout, ending and a post text per platform are all its call (`shorts-brief.md`). It is not a
clipper: the old yt-shorts-maker approach (pick a segment, crop, add a title) was rejected by the presenter.

```bash
# A long video edited by this repository: pass its job dir or its YouTube id (looked up in ~/video-jobs/*/out/youtube_upload.json)
opus_free_edit/start_shorts.sh <long job dir | video id | video file> ~/video-jobs/<yyyymmdd-topic>-shorts
```

| step | script | notes |
|---|---|---|
| transcript, proxy, frames, contact sheets of the finished video | `prepare.sh` | same as the long edit |
| the long job linked as `long/` | `run_shorts.sh` | raw green-screen recording, slides, えびフライ clips, EDIT_NOTES |
| the shorts edit | `claude -p` with `shorts-brief.md` | `platforms.json` (= `shorts_platforms.json`) gives limits, safe zones and sources |
| fallback voice flagged | `tts_guard.py report` | as in the long edit |
| size, codec, length per platform, stereo, no YouTube call-to-action in post texts | `check_shorts.py` | `STATUS` ends `failed` when a short breaks a rule |

Output: `out/<id>.mp4` (or one file per platform), `out/shorts.json` (files and post texts per platform),
`out/SHORTS_NOTES.md` (the planning memo), `out/<id>_sheet.jpg`. Nothing is uploaded or posted.
Researched short-form techniques: `editing-techniques.md` §5.
